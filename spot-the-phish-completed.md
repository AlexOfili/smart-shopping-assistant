# Spot the Phish 

## Message decisions

1. **Real** — The sender uses the expected `knull.co.uk` domain and gives a normal deadline without asking for credentials, money or a link click.
2. **Phish** — The real-looking name hides the unrelated `secure-verify.net` domain, then uses urgency, a threat and a credential-verification link.
3. **Verify first** — The `github.com` sender may be genuine, but an unexpected SSH-key alert is serious. Do not use the email link; open GitHub independently and check **Settings → SSH and GPG keys** and the security log.
4. **Phish** — The domain uses `knuII.co.uk` with capital `I` characters instead of the real spelling. It also asks for a passcode, creates urgency and tells the recipient to hide the request from Luca.
5. **Real** — It comes from the expected `knull.co.uk` domain, matches Mia's safeguarding role and does not ask for a secret, payment or risky action.
6. **Phish** — `render-billing-alerts.com` is not Render's normal domain. The message uses a payment threat and a short deadline to push the user to a fake billing page.
7. **Verify first** — It arrives from a personal Gmail account and encourages comparison before submission. Confirm with Priya through a known channel and navigate to GitHub independently before opening anything or sharing your own work.
8. **Phish** — The certificate domain is unrelated, the timing is suspicious and a ZIP file asking the user to “enable content” is a strong malware warning.

## A. Which two are trying to get something from you?

- **Message 4** is trying to obtain the staff-console passcode.
- **Message 7** is trying to draw out access to, comparison with or disclosure of your submission work. Even if Priya is real, verify the request before sharing anything.

## B. What should you do about message 3?

Open a new browser tab or the GitHub app yourself, sign in through the normal route and inspect the account's SSH keys and security log. Remove the key and secure the account if it is unfamiliar; do not click any button or link in the email.

## C. My two-line rule

**Stop when urgency is used to make me share, pay, sign in or open a file.**  
**Verify the sender and request through a separate trusted route before acting.**

## Important reporting note

A real message like number 4 should be forwarded to Luca and Mia immediately. A request to hide something from a mentor is itself a reason to tell the mentor.
